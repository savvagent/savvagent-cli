# egui Front-End — Foundation (Plan 1 of 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a native `eframe`/`egui` front-end *alongside* the existing ratatui TUI that opens a window, paints the conversation log + plugin slots + footer from the plugin render model, and runs a full turn from a prompt — without touching the plugin trait surface, host, or the existing TUI.

**Architecture:** A new `egui_app` module and a `savvagent-gui` binary host an `eframe::App`. Its `update()` drains the existing `worker_rx` channel, paints from a cached "render model" produced on a background tokio task (so the sync UI thread never `.await`s or locks plugin mutexes), and routes input through new pure conversion functions that mirror the existing `plugin/convert.rs` boundary but target egui types. The ratatui TUI binary remains the default and stays green; this plan adds code, it does not delete or retype anything the TUI uses.

**Tech Stack:** Rust, `eframe`/`egui`, `tokio` (existing multi-thread runtime), the existing `savvagent-host`/`savvagent-plugin` crates. Conversions are pure functions tested with `cargo test`; the window is verified by running it.

**Migration roadmap (context — not this plan's scope):**
- **Plan 1 (this doc):** foundation — shell, render-model bridge, color/text/key conversions, conversation log, slots, footer, prompt, turn execution.
- Plan 2: screen stack + modals (`Screen::render` lines + chrome as egui windows/panels).
- Plan 3: heavy widgets — code editor (`egui_code_editor`), markdown (`egui_commonmark`), file picker, `MultiSelectList`.
- Plan 4: canvas — Blitz RGBA8 → `egui` texture; delete `ratatui-image`/`coords.rs`.
- Plan 5: teardown — flip default to GUI, retype `Palette` to `Color32`, remove ratatui/crossterm/tui-* deps, delete dead TUI code, parity sweep.

Spec: `docs/superpowers/specs/2026-05-26-v0.19.0-egui-frontend-design.md`.

**Non-breaking rule for this plan:** Do NOT change the type of any field or function the ratatui TUI consumes (`Palette` stays `ratatui::style::Color`-backed; `plugin/convert.rs`'s ratatui sink stays). New egui code lives in new files and reads the existing `Palette` via *new* converter functions. `cargo build` (default TUI binary) and `cargo test --workspace` must stay green after every task.

/// Resolve a `ThemeColor` (including semantic slots) to an egui `Color32`.
/// Bridges through the existing ratatui resolver so the two sinks agree.
pub fn theme_color_to_color32(c: ThemeColor, palette: &Palette) -> Color32 {
    let rat = crate::plugin::convert::theme_color_to_ratatui(c, palette);
    ratatui_color_to_color32(rat, palette)
}

/// Convert a resolved `ratatui::style::Color` to `Color32`. Named ANSI colors
/// use egui's standard sRGB values; `Indexed` uses the xterm-256 table that
/// `editor_theme::color_to_hex` already relies on; `Reset` falls back to the
/// palette foreground.
fn ratatui_color_to_color32(c: ratatui::style::Color, palette: &Palette) -> Color32 {
    use ratatui::style::Color as C;
    match c {
        C::Rgb(r, g, b) => Color32::from_rgb(r, g, b),
        C::Black => Color32::from_rgb(0, 0, 0),
        C::Red => Color32::from_rgb(170, 0, 0),
        C::Green => Color32::from_rgb(0, 170, 0),
        C::Yellow => Color32::from_rgb(170, 85, 0),
        C::Blue => Color32::from_rgb(0, 0, 170),
        C::Magenta => Color32::from_rgb(170, 0, 170),
        C::Cyan => Color32::from_rgb(0, 170, 170),
        C::Gray => Color32::from_rgb(170, 170, 170),
        C::DarkGray => Color32::from_rgb(85, 85, 85),
        C::LightRed => Color32::from_rgb(255, 85, 85),
        C::LightGreen => Color32::from_rgb(85, 255, 85),
        C::LightYellow => Color32::from_rgb(255, 255, 85),
        C::LightBlue => Color32::from_rgb(85, 85, 255),
        C::LightMagenta => Color32::from_rgb(255, 85, 255),
        C::LightCyan => Color32::from_rgb(85, 255, 255),
        C::White => Color32::from_rgb(255, 255, 255),
        C::Indexed(i) => {
            let (r, g, b) = xterm_256_rgb(i);
            Color32::from_rgb(r, g, b)
        }
        C::Reset => ratatui_color_to_color32(
            crate::plugin::convert::theme_color_to_ratatui(ThemeColor::Fg, palette),
            palette,
        ),
    }
}
```

use egui::text::{LayoutJob, TextFormat};
use egui::{FontId, FontFamily};
use savvagent_plugin::{StyledLine, StyledSpan, TextMods};

/// Build a `(text, TextFormat)` pair for one styled span at the given font
/// size. The log/screen model is monospace, so `FontFamily::Monospace`.
pub fn styled_span_to_format(
    span: &StyledSpan,
    palette: &Palette,
    size: f32,
) -> (String, TextFormat) {
    let color = span
        .fg
        .map(|c| theme_color_to_color32(c, palette))
        .unwrap_or_else(|| theme_color_to_color32(ThemeColor::Fg, palette));
    let background = span
        .bg
        .map(|c| theme_color_to_color32(c, palette))
        .unwrap_or(Color32::TRANSPARENT);
    let TextMods { bold: _bold, italic, underline, strikethrough, dim: _dim } =
        normalize_mods(span.modifiers);
    let mut fmt = TextFormat {
        font_id: FontId::new(size, FontFamily::Monospace),
        color,
        background,
        italics: italic,
        ..Default::default()
    };
    if underline {
        fmt.underline = egui::Stroke::new(1.0, color);
    }
    if strikethrough {
        fmt.strikethrough = egui::Stroke::new(1.0, color);
    }
    (span.text.clone(), fmt)
}

/// Convert a styled line into a `LayoutJob` (one section per span).
pub fn styled_line_to_job(line: &StyledLine, palette: &Palette, size: f32) -> LayoutJob {
    let mut job = LayoutJob::default();
    for span in &line.spans {
        let (text, fmt) = styled_span_to_format(span, palette, size);
        job.append(&text, 0.0, fmt);
    }
    job
}

/// Mirror the fields of `TextMods` into locals, tolerant of `#[non_exhaustive]`.
fn normalize_mods(m: TextMods) -> TextMods {
    m
}
```

> `TextMods`' exact fields must match what `savvagent-plugin` defines (`bold`, `italic`, `underline`, `reverse`, `dim` per `styled.rs`). If `strikethrough` does not exist, drop it; if `reverse` exists, decide rendering (swap fg/bg) — for the foundation, ignore `reverse` and `dim` (note as a Plan 5 fidelity item). Read `crates/savvagent-plugin/src/styled.rs` to confirm the field set before writing, and adjust the destructure accordingly. Remove the placeholder `normalize_mods` if not needed.

use savvagent_plugin::{KeyCodePortable, KeyEventPortable, KeyMods};

/// Convert a *press* egui event into a `KeyEventPortable`. Returns `None` for
/// key releases and events that carry no key meaning. `Event::Text` maps to a
/// `Char` so typed characters reach prompt/editor consumers.
pub fn egui_event_to_portable(ev: &egui::Event) -> Option<KeyEventPortable> {
    match ev {
        egui::Event::Text(s) => {
            let c = s.chars().next()?;
            Some(KeyEventPortable {
                code: KeyCodePortable::Char(c),
                modifiers: KeyMods::default(),
            })
        }
        egui::Event::Key { key, pressed: true, modifiers, .. } => Some(KeyEventPortable {
            code: egui_key_to_portable(*key)?,
            modifiers: KeyMods {
                ctrl: modifiers.ctrl,
                alt: modifiers.alt,
                shift: modifiers.shift,
                meta: modifiers.mac_cmd || modifiers.command,
            },
        }),
        _ => None,
    }
}

fn egui_key_to_portable(k: egui::Key) -> Option<KeyCodePortable> {
    use egui::Key as K;
    Some(match k {
        K::Enter => KeyCodePortable::Enter,
        K::Escape => KeyCodePortable::Esc,
        K::Backspace => KeyCodePortable::Backspace,
        K::Tab => KeyCodePortable::Tab,
        K::Insert => KeyCodePortable::Insert,
        K::Delete => KeyCodePortable::Delete,
        K::ArrowUp => KeyCodePortable::Up,
        K::ArrowDown => KeyCodePortable::Down,
        K::ArrowLeft => KeyCodePortable::Left,
        K::ArrowRight => KeyCodePortable::Right,
        K::Home => KeyCodePortable::Home,
        K::End => KeyCodePortable::End,
        K::PageUp => KeyCodePortable::PageUp,
        K::PageDown => KeyCodePortable::PageDown,
        K::A => KeyCodePortable::Char('a'),
        K::S => KeyCodePortable::Char('s'),
        // Remaining letter/number keys map analogously; fill in the full
