# egui Front-End — Heavy Widgets (Plan 3 of 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Light up the three heavy widgets the `savvagent gui` front-end still stubs or routes through the generic line painter: a real **code editor** for the `view-file`/`edit-file` marker screens (replacing the `view.rs:88-92` Plan-2 placeholder), a **file picker** the GUI prompt can trigger to insert `@<path>` references, and a **portable `MultiSelectList`** that drops the `crossterm`-bridge `LspPickerScreen` is using today.

**Architecture:** A new `crates/savvagent/src/egui_app/widgets/` submodule houses the GUI-specific widget integrations: an `egui_code_editor` color-theme adapter built from the existing `Palette`, a tiny `EditorBuffer` (path + text + dirty flag) cached on `SavvagentApp`, and a per-frame paint hook that swaps in the editor for marker screens. The file picker is an `egui-file-dialog` modal opened by `Ctrl+O` from the prompt; on confirmation the chosen path is appended as `@<path>` to the prompt buffer. `MultiSelectList::on_key` switches from `crossterm::event::KeyEvent` to `savvagent_plugin::KeyEventPortable` so both the egui and the ratatui call paths feed it portable keys; `LspPickerScreen` drops its `portable_to_crossterm` helper. The Plan-2 generic line painter keeps rendering everything else.

**Tech Stack:** Rust, `eframe`/`egui` 0.32, `egui_code_editor` 0.2.17, `egui-file-dialog` 0.11.0, the existing `savvagent-plugin` `Screen`/`Effect` surface. Conversions are pure functions tested with `cargo test`; widget behavior is verified by running the window.

**Migration roadmap (context — not this plan's scope):**
- Plan 1 (shipped, #104): foundation — shell, render-model bridge, conversions, home log/slots/footer, prompt, turn execution.
- Plan 2 (shipped, #105): screen stack + modals — render top `Screen` as egui overlay, route input, open via slash + keybindings.
- **Plan 3 (this doc):** heavy widgets — code editor for view/edit screens, file picker for prompt completion, portable `MultiSelectList` for `LspPickerScreen`.
- Plan 4: canvas — Blitz RGBA8 → egui texture; delete `ratatui-image`/`coords.rs`.
- Plan 5: teardown — flip default to GUI, retype `Palette` to `Color32`, remove ratatui/crossterm.

Spec: `docs/superpowers/specs/2026-05-26-v0.19.0-egui-frontend-design.md` (§6 interactive surfaces).

**Non-breaking rule for this plan:** Do NOT modify `run_app`, `ui.rs`, or any ratatui/TUI rendering. New behavior lives in `crates/savvagent/src/egui_app/widgets/*` and in the small `MultiSelectList`/`LspPickerScreen` change that flips one widget's `on_key` signature (the ratatui TUI's only call path for `MultiSelectList` already converts crossterm → portable before reaching the screen-stack, so the TUI is behavior-identical after the swap). `cargo build`, `cargo test --workspace`, and `cargo clippy --workspace --all-targets -- -D warnings` (stable) must stay green after every task; the TUI stays behavior-identical.

**Intentional scope reduction — markdown widget deferred:** The Plan-1/2 roadmap listed `egui_commonmark` for the changelog screen. Plan 3 does NOT add it. The Plan-2 generic styled-line painter already renders `ChangelogScreen`'s `Vec<StyledLine>` (produced via `markdown_to_styled_lines` in `changelog/screen.rs:180`) correctly in the egui modal. Swapping to `egui_commonmark` would require either (a) a defaulted method on the `Screen` trait to expose raw markdown (the spec's "zero changes to the plugin trait surface" rule forbids this), or (b) plumbing the changelog `Arc<Mutex<ChangelogState>>` through `apply_effects::open_screen` into a GUI-only `App` slot so the egui painter can read raw markdown (invasive, GUI-only state on `App`). Per the [`egui: don't chase TUI parity pre-adoption`](../../../.claude/projects/-home-robhicks-dev-ai-coder/memory/feedback_egui_no_tui_parity.md) note, the line path is sufficient and shipping a markdown widget upgrade is not worth the violation. If a future iteration changes this trade-off (e.g. links/images in CHANGELOG), Plan 6 or a follow-up can add the trait method.

  - `egui-file-dialog = "0.11.0"` — last 0.11.x; requires egui ^0.32 (confirmed via the same API).
- **The Plan-2 placeholder lives at `crates/savvagent/src/egui_app/view.rs:88-92`** — `if id == "view-file" || id == "edit-file" { ui.weak("[file view/edit — Plan 3]"); }` — Plan 3 replaces this block with the editor paint.
- **`view-file` and `edit-file` are marker screens** (`view_file/screen.rs:19`, `edit_file/screen.rs:19`). Their `render()` returns `vec![]`; `on_key` only forwards `Esc` → `CloseScreen` (`view_file/screen.rs:43-51`) and additionally `Ctrl-S` → `Effect::SaveActiveFile` for edit (`edit_file/screen.rs:40-53`). The screen's keys are routed by the Plan-2 path in `egui_app/mod.rs:404-433`.
- **File content is loaded into `App::editor` by `apply_effects::open_screen` BEFORE the screen pushes** (`plugin/effects.rs:614-625`) via `App::load_file_into_editor` (`app.rs:1592-1623`). The screen close path calls `App::clear_active_editor` (`effects.rs:55-66`, `app.rs:1628-1631`). **Plan 3 reads `App::active_file_path` to know which file to load into the GUI's `EditorBuffer`** — the path-string is the same in both the TUI and GUI flows because it comes from the same `Effect::OpenScreen { args: ScreenArgs::ViewFile { path } }` slash dispatch.
- **`App::save_file`** (`app.rs:1670-1684`) writes `self.editor.get_content()` (the ratatui editor's buffer). The GUI's editor buffer is separate, so Plan 3 saves via a new helper rather than emitting `Effect::SaveActiveFile` (which would write the stale ratatui buffer — silently losing every GUI edit). The GUI intercepts `Ctrl-S` before key routing.
- **`MultiSelectList::on_key`** (`plugin/widgets/multi_select_list.rs:161`) takes `crossterm::event::KeyEvent`. Only caller: `LspPickerScreen::on_key` (`plugin/builtin/lsp_installer/screen.rs:90-112`), which translates `KeyEventPortable` → `crossterm::event::KeyEvent` via `portable_to_crossterm` (`screen.rs:121-143`). The TUI's input pipe converts the OTHER way (`crossterm::event::KeyEvent` → `KeyEventPortable`) before reaching the screen-stack, so once the widget speaks `KeyEventPortable` the TUI flow stays correct (and the helper plus the `crossterm` dep on `MultiSelectList` go away).
- **Editor theme today is hex-string-based**: `build_editor_theme(&Palette)` (`plugin/builtin/themes/editor_theme.rs:39-80`) returns `Vec<(token, hex_color)>` for `ratatui-code-editor`'s syntax map. Plan 3 adds a **parallel** `palette_to_color_theme(&Palette) -> egui_code_editor::ColorTheme` for the egui editor; the ratatui-side function stays unchanged.
- **`egui_code_editor::ColorTheme`** is the type that holds background + per-token colors (verify exact field names/casing against the 0.2.17 docs/source while implementing — version pin is firm; field names are not yet hand-confirmed).
- **`egui-file-dialog::FileDialog`** is a per-app state struct; `dialog.open()` → `dialog.update(ctx)` per frame → `dialog.take_picked()` returns `Some(PathBuf)` once. Verify exact method names against the 0.11.0 docs while implementing.
- **`SavvagentApp::prompt: String`** (`egui_app/mod.rs:85`) is the GUI prompt buffer the `TextEdit::multiline` in `paint_prompt` binds to. Plan 3 mutates it from the file-picker confirm path.

```rust
/// Render a `Color32` as `#RRGGBB` (ColorTheme stores hex strings).
fn color32_to_hex(c: egui::Color32) -> &'static str {
    // egui_code_editor's ColorTheme stores `&'static str` for each
    // color. We must intern dynamic strings — `Box::leak` is the
    // pragmatic answer here; the leak is one short string per slot per
    // theme switch, well under the lifetime-cost line.
    Box::leak(format!("#{:02X}{:02X}{:02X}", c.r(), c.g(), c.b()).into_boxed_str())
}
```

- [x] **Step 1: Define `EditorBuffer`**

Replace the stub contents of `crates/savvagent/src/egui_app/widgets/editor.rs` with:

```rust
//! GUI editor state + paint pass for the `view-file` / `edit-file`
//! marker screens. The buffer lives on `SavvagentApp` (not on `App`,
//! which still owns the ratatui editor for the TUI path); it is
//! lazy-loaded from `App::active_file_path` the first frame after a
//! marker screen opens and cleared when the screen pops.

use std::path::{Path, PathBuf};

/// Per-open file state for the GUI editor. Owns the text the
/// `egui_code_editor::CodeEditor` widget mutates in-place, plus the path
/// it came from so save knows where to write.
#[derive(Debug, Clone)]
pub struct EditorBuffer {
    /// Disk path of the open file. Set on load.
    pub path: PathBuf,
    /// In-memory buffer. The widget mutates this on every keystroke
    /// when the screen is `edit-file`. Untouched for `view-file`.
    pub text: String,
    /// Whether the buffer has unsaved changes since load. Bumped to
    /// true by `mark_dirty` whenever the widget reports a text change;
    /// reset to false on successful save.
    pub dirty: bool,
}

impl EditorBuffer {
    /// Load `path` from disk into a fresh buffer.
    pub fn load(path: &Path) -> std::io::Result<Self> {
        let text = std::fs::read_to_string(path)?;
        Ok(Self {
            path: path.to_path_buf(),
            text,
            dirty: false,
        })
    }

    /// Mark dirty after a widget edit reported text changed.
    pub fn mark_dirty(&mut self) {
        self.dirty = true;
    }

    /// Write the buffer text to disk and clear `dirty` on success.
```

```rust
pub fn paint_editor(
    ui: &mut egui::Ui,

    palette: &crate::palette::Palette,
    editable: bool,
) {

    // even when "disabled"). If the response says changed and we're

    if editable && response.response.changed() {

    }

/// Best-effort path → syntax mapping for the editor. Falls back to
/// `Syntax::rust()` for unknown extensions so the editor still paints
/// (with possibly-wrong highlighting) rather than failing.
fn syntax_for_path(path: &std::path::Path) -> egui_code_editor::Syntax {
    use egui_code_editor::Syntax;
    let ext = path
        .extension()
        .and_then(|s| s.to_str())
        .unwrap_or("")
        .to_ascii_lowercase();
    match ext.as_str() {
        "rs" => Syntax::rust(),
        "py" => Syntax::python(),
        "js" | "mjs" | "ts" | "tsx" | "jsx" => Syntax::javascript(),
        "sh" | "bash" => Syntax::shell(),
        // egui_code_editor 0.2.17 ships these built-ins (confirm against
        // its source; add new arms here if a language is missing).
        _ => Syntax::rust(),
    }
}

/// Ensure `state.editor_buffer` matches the currently-open marker
/// screen. Called once at the top of `update()` per frame. The buffer
/// is loaded from `app.active_file_path` (set by
/// `App::load_file_into_editor` when the screen pushes) and cleared
/// when no marker screen is on top.
pub fn ensure_buffer_for_active_screen(
    editor_buffer: &mut Option<EditorBuffer>,
    app: &crate::app::App,
) {
    let top_id = app.screen_stack.top().map(|(s, _)| s.id());
    let is_marker = matches!(top_id.as_deref(), Some("view-file") | Some("edit-file"));

    if !is_marker {
        // Screen closed (or some other modal is on top): drop our buffer.
        // App::clear_active_editor already nulled active_file_path; the
        // ratatui side mirrors this drop.
        *editor_buffer = None;
        return;
    }

    let want_path = match &app.active_file_path {
        Some(p) => p.clone(),
        None => {
            // Marker screen is open but the active path was nulled
            // (load failed, or a teardown raced). Render nothing.
            *editor_buffer = None;
            return;
        }
    };

    let needs_load = match editor_buffer {
        Some(buf) => buf.path != want_path,
        None => true,
    };
    if needs_load {
        match EditorBuffer::load(&want_path) {
            Ok(buf) => *editor_buffer = Some(buf),
            Err(err) => {
                tracing::warn!(error = %err, path = %want_path.display(),
                    "GUI editor: load failed");
                *editor_buffer = None;
            }
        }
    }
}
```

```rust
use std::path::{Path, PathBuf};

use egui_file_dialog::FileDialog;

/// State for the GUI file picker. Default-constructed once when
/// `SavvagentApp` is built; the dialog itself is lazy-initialized in
/// `Self::new` and re-used across opens.
pub struct FilePicker {
    inner: FileDialog,
}

impl Default for FilePicker {
    fn default() -> Self {
        Self::new()
    }
}

impl FilePicker {
    pub fn new() -> Self {
        Self {
            inner: FileDialog::new(),
        }
    }

    /// Open the dialog in pick-file mode. Idempotent on consecutive
    /// calls within one frame.
    pub fn open(&mut self) {
        self.inner.pick_file();
    }

    /// Paint + drive the dialog. Must be called every frame the dialog
    /// might be visible.
    pub fn update(&mut self, ctx: &egui::Context) {
        self.inner.update(ctx);
    }

    /// Consume a confirmed pick (the user clicked OK). Returns `None`
    /// while the dialog is still open or after the user cancelled.
    pub fn take_picked(&mut self) -> Option<PathBuf> {
        self.inner.take_picked()
    }
}

/// Splice an `@<path>` reference into `prompt`, mimicking the TUI's
/// `App::file_picker_select` behavior (`app.rs:1542-1571`): if the
/// prompt contains a trailing `@`, replace from the last `@` to end with
/// `@<path>`; otherwise append ` @<path>`.
pub fn splice_at_reference(prompt: &mut String, path: &Path) {
    let path_str = path.display().to_string();
    if let Some(idx) = prompt.rfind('@') {
        prompt.truncate(idx);
        prompt.push('@');
        prompt.push_str(&path_str);
    } else {
        if !prompt.is_empty() && !prompt.ends_with(char::is_whitespace) {
            prompt.push(' ');
        }
        prompt.push('@');
        prompt.push_str(&path_str);
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn splice_replaces_trailing_at_marker() {
        let mut prompt = String::from("explain @");
        splice_at_reference(&mut prompt, Path::new("src/main.rs"));
        assert_eq!(prompt, "explain @src/main.rs");
    }

    #[test]
    fn splice_appends_when_no_at_marker() {
        let mut prompt = String::from("explain");
        splice_at_reference(&mut prompt, Path::new("src/main.rs"));
        assert_eq!(prompt, "explain @src/main.rs");
    }

    #[test]
    fn splice_appends_without_double_space() {
        let mut prompt = String::from("explain ");
        splice_at_reference(&mut prompt, Path::new("a.rs"));
        assert_eq!(prompt, "explain @a.rs");
    }

    #[test]
    fn splice_into_empty_prompt() {
        let mut prompt = String::new();
        splice_at_reference(&mut prompt, Path::new("a.rs"));
        assert_eq!(prompt, "@a.rs");
    }
}
```
