# egui Front-End — Teardown + v0.19.0 release (Plan 5 of 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make egui the only front-end. Delete the ratatui/crossterm TUI and every crate dep it pulled in, retype `Palette` to `egui::Color32` storage, run a parity checklist in the running window, and ship the v0.19.0 release (Plans 1–5 rolled into a single tag).

**Architecture:** Reverse Plan 1's "GUI lives under a `gui` subcommand; TUI is the default" decision — the binary's `main()` calls `egui_app::run()` unconditionally and the entire ratatui paint/loop/lifecycle (`ui.rs`, `tui.rs`, `splash.rs`, `run_app`, the `App` widget fields, the ratatui screen adapters, `theme_color_to_ratatui`/`styled_*_to_ratatui` converters, the `ratatui-image` canvas blitter, `CanvasRegistry`'s image fields, `savvagent-canvas::coords`) is deleted. `Palette` switches from `ratatui::style::Color` to `egui::Color32` storage so the egui sink no longer bridges through a `ratatui::Color` intermediate, and `build_editor_theme` reads `Color32` directly. Eight TUI crate deps (`crossterm`, `ratatui`, `ratatui-image`, `ratatui-themes`, `tui-markdown`, `tui-textarea`, `ratatui-explorer`, `ratatui-code-editor`) are removed from both the workspace root and `crates/savvagent/Cargo.toml`; `image` stays (Blitz uses it). The release adds the v0.19.0 CHANGELOG entry, bumps the workspace version 0.18.0 → 0.19.0, refreshes the README/CLAUDE.md/init_tracing comment to reflect the GUI-default reality, and pushes the v0.19.0 tag (cargo-dist owns the GitHub Release on tag push).

**Tech Stack:** Rust 2024, eframe/egui 0.32, the existing `savvagent-plugin` `Screen`/`Effect` surface, the Plan 1–4 egui shell (`egui_app/{mod,view,convert,fonts,render_model,screen,widgets}.rs`). cargo-dist 0.31.0 on tag push.

**Migration roadmap (context — not this plan's scope):**
- Plan 1 (shipped, #104): foundation — shell, render-model bridge, conversions, home log/slots/footer, prompt, turn execution.
- Plan 2 (shipped, #105): screen stack + modals — render top `Screen` as egui overlay, route input, open via slash + keybindings.
- Plan 3 (shipped, #106): heavy widgets — code editor for view/edit screens, file picker for prompt completion, portable `MultiSelectList` for `LspPickerScreen`.
- Plan 4 (shipped, #107): canvas — Blitz RGBA8 → egui texture; shared `canvas_input` module; `ratatui-image`/`coords.rs` left for Plan 5.
- **Plan 5 (this doc):** teardown — flip default to GUI, retype `Palette` to `Color32`, delete ratatui/crossterm/tui-* code + deps, ship v0.19.0.

Spec: `docs/superpowers/specs/2026-05-26-v0.19.0-egui-frontend-design.md` (sequence step 9; goals "Replace the entire ratatui/crossterm front-end" + non-goal "Not keeping the ratatui TUI alongside the GUI. crossterm/ratatui dependencies are removed at the end of the migration").
