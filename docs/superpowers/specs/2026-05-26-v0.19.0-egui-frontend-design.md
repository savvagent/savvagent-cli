# egui front-end — replacing the ratatui TUI (v0.19.0) — design

Date: 2026-05-26
Status: drafted, awaiting user review before plan
Supersedes: nothing (the ratatui TUI is removed, not deprecated in place)
Related:
- `docs/superpowers/specs/2026-05-12-v0.9.0-plugin-system-design.md` — the framework-neutral `Plugin`/`Screen` trait surface (`Vec<StyledLine>`, `KeyEventPortable`, `Region`, closed `Effect` enum) that makes this rewrite confinable to one crate
- `docs/superpowers/specs/2026-05-21-inline-html-canvas-design.md` — the Blitz→RGBA8 canvas pipeline (`savvagent-canvas`) whose terminal blitting layer this design deletes
- `docs/superpowers/specs/2026-05-25-external-plugins-design.md` — sub-project D (v0.18.0); ships immediately before this work begins
- `docs/superpowers/specs/2026-05-12-v0.8.0-theme-picker-design.md` — the `Palette` / `ThemeColor` semantic-slot model this design re-targets to `Color32`

## Context

Savvagent's front-end is today a ratatui/crossterm terminal UI in
`crates/savvagent`. The core architecture is "everything is MCP-shaped"
and the UI sits on a deliberately framework-neutral plugin layer: the
`savvagent-plugin` trait surface (designed under v0.9.0's WIT-portability
rules) has **zero ratatui dependency**. Plugins and screens render to
owned `Vec<StyledLine>`, consume `KeyEventPortable`, lay out in an
abstract `Region`, and return a closed-vocabulary `Effect`. The
`savvagent-host` turn loop, providers, and tools are entirely
UI-agnostic.

As a result, all ratatui/crossterm coupling lives in roughly **8 files
importing `ratatui` and 10 importing `crossterm`**, all inside
`crates/savvagent`. The render path (`ui.rs`), the input conversion
(`plugin/convert.rs`), terminal lifecycle (`tui.rs`), the main loop
(`main.rs`), the palette (`palette.rs`), and a handful of interactive
widgets are the entire blast radius.

This design replaces that front-end with a native `eframe`/`egui` GUI.
egui was chosen over iced, Slint, and Tauri because it is the only
candidate that is **immediate-mode** like both ratatui and the plugin
render contract (`render_slot`/`Screen::render` are documented as "called
every frame; must be cheap and side-effect-free"). The existing
immediate-mode loop and worker-channel drain therefore carry over almost
unchanged, where iced/Slint would force a control-flow inversion and
Tauri would break the project's Rust-only identity by introducing a
JS/web layer.

This is a v0.19.0 initiative that begins after sub-project D
(external-plugins, v0.18.0) lands, so the two large efforts do not touch
overlapping surfaces at once.

## Problem

A terminal UI caps what savvagent can render and how it can be operated:

1. **Rich content is a fight.** The inline HTML canvas (v0.17.0) renders
   HTML via Blitz to an RGBA8 buffer, then blits it through
   `ratatui-image` with cell↔pixel coordinate math and per-terminal
   image-protocol detection. It only works on terminals that support an
   image protocol, and reserves fixed character rows as placeholders.
2. **Text fidelity is grid-bound.** Everything is character cells; fonts,
   proportional text, smooth scrolling, and real layout are unavailable.
3. **Interaction is keyboard-only by default**, with mouse support
   bolted on through crossterm mouse capture (which silently fails under
   tmux/screen) and a Kitty-keyboard-protocol workaround for Shift+Enter.

The plugin layer was designed framework-neutral precisely so the
presentation could change without rewriting the ~100 plugin/screen
files. This design exercises that affordance.

## Goals

- Replace the entire ratatui/crossterm front-end in `crates/savvagent`
  with a native `eframe`/`egui` window, at **feature parity** with the
  current TUI.
- Keep the project **Rust-only** (no web/JS/IPC layer).
- Make **zero changes** to `savvagent-host`, `savvagent-protocol`,
  `savvagent-mcp`, the provider/tool crates, or the `savvagent-plugin`
  trait surface. All ~100 plugin/screen files keep compiling and
  behaving identically.
- Turn the canvas from a terminal-image hack into a native texture,
  deleting the `ratatui-image` / cell↔pixel layer.

## Non-goals

- **Not** keeping the ratatui TUI alongside the GUI. crossterm/ratatui
  dependencies are removed at the end of the migration. (Headless and
  example/host smoke-test paths that don't use the TUI are unaffected.)
- **Not** changing the plugin trait surface, the `Effect`/`HostEvent`
  vocabularies, the slot ids, or the screen-stack model.
- **Not** introducing accessibility work in this pass (egui's AccessKit
  integration is noted as a follow-up).
- **Not** redesigning the visual language of the app beyond what is
  required to render the existing `StyledLine`/screen model faithfully in
  a window.

## Approach

A new `eframe::App` implementation becomes the shell, the render boundary
in `convert.rs`/`ui.rs`/`palette.rs` gains an egui sink, and the
interactive widgets are rebuilt on egui equivalents. The plugin runtime
(registry, indexes, slot router, screen stack, keybinding router, effect
dispatch) is reused verbatim — only the types at the very edge
(`crossterm::KeyEvent`, `ratatui::Color`/`Span`/`Line`/`Frame`) are
swapped.

### 1. Shell — `eframe::App` replaces the `main.rs` loop and `tui.rs`

The current loop (`crates/savvagent/src/main.rs`, `run_app`) is already
immediate-mode:

```text
loop {
    frame_data = compute_home_frame_data(app, area).await;  // async slot pre-render
    terminal.draw(|f| ui::render(app, f, &frame_data));     // sync whole-frame paint
    while let Ok(msg) = worker_rx.try_recv() { ... }         // non-blocking channel drain
    if event::poll(50ms) { handle(event::read()) }           // input
}
```

This maps onto `eframe`:

- A new `SavvagentApp` struct holds the existing `App` state, the
  `HostSlot` (`Arc<RwLock<Option<Arc<Host>>>>`), the `worker_rx`
  receiver, a `tokio::runtime::Handle`, and the cached render model
  (see §2).
- `impl eframe::App for SavvagentApp { fn update(&mut self, ctx, frame) }`
  is called per frame by winit. Each `update`:
  1. drains `worker_rx` with `try_recv()` (the existing match arms move
     here essentially unchanged);
  2. paints the UI (§3) from cached render data;
  3. reads input from `ctx.input(...)` and routes it (§5);
  4. calls `ctx.request_repaint()` (or `request_repaint_after`) while a
     turn is streaming or the worker channel is non-empty, so egui keeps
     animating; when idle, egui parks and repaints only on input.
- **Threading.** winit requires the event loop on the main thread, so
  `eframe::run_native` runs on `main`. A multi-thread tokio runtime is
  started before it; its `Handle` is moved into `SavvagentApp` so turn
  workers spawn with `handle.spawn(...)` exactly as today. The
  async-in-`update` problem (egui's `update` is sync) is handled by §2,
  not by blocking.
- `tui.rs` (raw mode, alternate screen, mouse capture, Kitty keyboard
  flags, panic-restore hook) is **deleted**. Window title/size/icon and
  close handling come from `eframe::NativeOptions` + viewport commands.

### 2. The sync/async bridge — generalize `HomeFrameData`

egui's `update()` cannot `.await`, but plugin slot rendering and
tool-call summaries are async today (`compute_home_frame_data` takes
read-locks on the plugin registry/indexes and awaits per contributor).
The current code already sidesteps this by pre-computing `HomeFrameData`
*before* the sync `terminal.draw`. We generalize that across frames:

- A background tokio task owns render-model production. On each tick (or
  on a "state changed" signal), it computes the latest slot lines
  (`home.banner`, `home.tips`, `home.footer.*`) and per-`Entry::Tool`
  summaries, and sends a `RenderModel` snapshot over a channel (or stores
  it in an `Arc<Mutex<RenderModel>>`).
- `update()` paints from the most recent `RenderModel` it has received —
  never locking a plugin mutex on the UI thread, never blocking.
- This is the same data shape as today's `HomeFrameData`
  (`Vec<StyledLine>` per slot + `Vec<ToolEntryRender>`); only the
  delivery changes from "awaited inline each frame" to "produced
  asynchronously, painted from cache."

### 3. Render boundary — egui sink in `convert.rs`, `ui.rs`, `palette.rs`

- **`palette.rs`:** `Palette`'s nine semantic slots (`fg`, `bg`,
  `border`, `accent`, `muted`, `error`, `success`, `warning`,
  `secondary`) change storage from `ratatui::style::Color` to
  `egui::Color32`. `from_upstream(ThemePalette)` and the hardcoded
  Dark/Light/HighContrast palettes resolve to `Color32`.
- **`convert.rs`:** add an egui sink alongside (eventually replacing) the
  ratatui one:
  - `theme_color_to_color32(ThemeColor, &Palette) -> Color32` (literal
    ANSI/indexed/RGB map directly; indexed uses the xterm-256 table
    already present in `editor_theme.rs::color_to_hex`; semantic slots
    resolve against the palette).
  - `styled_span_to_layoutjob_section(...)` and
    `styled_line_to_layoutjob(...)` building an `egui::text::LayoutJob`
    (one `TextFormat` section per span: fg/bg/`TextMods`→
    italics/underline/strikethrough/weight).
  - `text_mods_to_text_format(TextMods)` replacing
    `text_mods_to_modifier`.
  - The ratatui `region_to_rect`/`rect_to_region`/`styled_*_to_ratatui`
    helpers are removed once `ui.rs` no longer calls them.
- **`ui.rs`:** rewritten against egui panels:
  - `TopBottomPanel::top` — header (provider/model line).
  - `CentralPanel` + `ScrollArea::vertical` — conversation log. Each
    `Entry` (`User`/`Assistant`/`Tool`/`RouteBadge`/`Note`/`Canvas`)
    becomes a labelled block; `Tool` rows paint the pre-rendered
    arg/result `StyledSpan`s from the cached model; `Canvas` paints a
    native texture (§ canvas).
  - `TopBottomPanel::bottom` — tips line, then the prompt widget, then
    the footer (the three `home.footer.*` slots).
  - Screens/modals paint as egui `Window`/overlay panels (§5).
- **`splash.rs`** is reimplemented as an egui-painted splash (or an
  initial `update` state) and dismissed on first input/timer.

### 4. `Region` stays line-based; the log/screens use a monospace font

`Region` keeps its `(x, y, width, height)` shape but its unit becomes
**logical rows/columns** measured by the runtime from the available
panel rect divided by a fixed monospace glyph size. Screens and slots
continue to return `Vec<StyledLine>`, and egui paints **one row per
line** in a bundled monospace font. This is the key decision that keeps
all ~100 plugin/screen files unchanged: they still think in lines, and
the runtime is responsible for turning a panel into a `Region` and a
`Vec<StyledLine>` into rows. Proportional fonts are used only inside the
purpose-built widgets (markdown, code editor) where layout is owned by
that widget, not by the line model.

### 5. Input — egui `ctx.input()` → `KeyEventPortable`

- New `egui_event_to_portable(...)` in `convert.rs` mirrors
  `key_event_to_portable`: `egui::Key` + `egui::Modifiers` →
  `KeyCodePortable` + `KeyMods`. Text input (`egui::Event::Text`) maps to
  `KeyCodePortable::Char`.
- The existing routing tree is preserved in `update()`:
  Ctrl-C/Ctrl-D quit → splash dismiss → screen-stack `on_key` (if the
  stack is non-empty) → home editing (prompt, file picker, prompt
  history, command palette, slash routing). The keybinding router and
  key-scope/chord resolution (`plugin/keybindings.rs`) are reused as-is
  because they operate on `KeyEventPortable`.
- Mouse: egui pointer events replace crossterm mouse events — scroll over
  the conversation, and clicks on a focused canvas (§ canvas). The
  crossterm mouse-capture caveat (tmux/screen) disappears.
- The `MultiSelectList` widget and the few pickers that currently
  pattern-match on `crossterm::KeyCode` are switched to `KeyEventPortable`
  (they already receive portable keys through the screen path; the direct
  crossterm matches in `multi_select_list.rs` are the only real change).

### 6. Interactive surfaces to rebuild

| Today (ratatui ecosystem) | egui replacement | Notes |
|---|---|---|
| Prompt — `tui-textarea` (`App::input_textarea`) | `egui::TextEdit::multiline` | prompt history, Ctrl+Z/Y undo-redo, Shift+Enter newline are native; submit on Enter |
| Code editor (view/edit file) — `ratatui-code-editor` (`App::editor`) | `egui_code_editor` (syntect) | reuse `build_editor_theme(&Palette)`; emit a syntect/`Color32` theme instead of `(token, hex)` pairs |
| Markdown (changelog) — `tui-markdown` | `egui_commonmark` | **removes** the ratatui 0.29↔0.30 version-mismatch hack in `changelog/screen.rs` (`markdown_to_styled_lines`) |
| File picker — `ratatui-explorer` (`App::file_explorer`) | egui collapsing tree or `egui-file-dialog` | preserve the directory-navigate vs file-select Enter semantics |
| `MultiSelectList<T>` (custom, `plugin/widgets/`) | egui filtered list | filter/cursor/selection/preview outcomes preserved |

### 7. Canvas — native texture, deleting the terminal-image layer

`savvagent-canvas` already renders HTML via Blitz to an **RGBA8 frame**
(`render_html_to_rgba` → `PixelFormat::Rgba8`). The TUI's job of blitting
that through `ratatui-image` with `coords.rs`/`CellPixelSize` math and
image-protocol detection is replaced by:

- `egui::ColorImage::from_rgba_unmultiplied([w, h], &bytes)` →
  `ctx.load_texture(...)` → an inline `ui.image(texture)` in the
  conversation log, sized to the document. The fixed `CANVAS_RESERVED_ROWS`
  placeholder and the source-code fallback path go away.
- Pointer events over the texture map (via egui local coords) directly to
  `HtmlCanvas::dispatch(MouseEventPortable)` — no cell→pixel conversion.
- Deleted as a consequence: the `ratatui-image` dependency, `coords.rs`
  (`CellPixelSize`/`CellRect`/`cell_to_pixel`/`contains_cell`), the
  image-protocol `Picker` setup, and the canvas-overlay rect plumbing in
  `ui.rs` (`render_canvas_overlays`, `canvas_content_area`,
  `render_canvas_image`, `render_canvas_source_fallback`).

### Module / dependency changes

New:
- `eframe`, `egui`, `egui_extras` (image/texture loaders), `egui_commonmark`,
  `egui_code_editor` (or syntect directly), a bundled monospace font.

Removed at the end of the migration:
- `ratatui`, `ratatui-themes`, `crossterm`, `tui-textarea`, `tui-markdown`,
  `ratatui-explorer`, `ratatui-code-editor`, `ratatui-image`.

Files rewritten or deleted in `crates/savvagent/src`:
- `tui.rs` — **deleted** (lifecycle moves to `eframe`/viewport).
- `main.rs` — loop + terminal setup replaced by `eframe::run_native` and
  `SavvagentApp`.
- `ui.rs` — rewritten against egui panels/widgets.
- `plugin/convert.rs` — egui sink replaces ratatui sink.
- `palette.rs` — `Color32` storage.
- `splash.rs` — egui splash.
- `app.rs` — widget-state fields retyped (`input_textarea`, `editor`,
  `file_explorer`) to their egui equivalents.
- `plugin/widgets/multi_select_list.rs` — `KeyEventPortable` input.
- `plugin/builtin/changelog/screen.rs` — `egui_commonmark` markdown.
- `plugin/builtin/themes/editor_theme.rs` — emit a `Color32`/syntect
  editor theme.

Unchanged: every other `plugin/builtin/*` screen, slot, and effect
handler (they already speak `StyledLine`/`KeyEventPortable`/`Effect`).

## Data flow (turn streaming)

```text
provider stream → Host::run_turn_streaming → TurnEvent
  → worker_tx (mpsc 128)
    → SavvagentApp::update drains worker_rx.try_recv()
      → translate_turn_event_to_host_event (plugin subscribers)
      → app.apply_turn_event / update_metrics
      → effects::dispatch_host_event
      → (on HtmlBlockStop) create canvas renderer → load egui texture
      → ctx.request_repaint()        // keep painting while streaming
```

The host-swap pattern is unchanged: `/connect` and `/disconnect` still
swap `Arc<RwLock<Option<Arc<Host>>>>`; worker tasks clone the
`Arc<Host>` under a brief read lock and drop the guard before awaiting.

## Testing strategy

- **Pure conversion functions** are unit-tested exactly as `convert.rs`
  is today: `theme_color_to_color32` (literal + semantic + per-theme),
  `egui_event_to_portable` (char/ctrl/unknown), `styled_*_to_layoutjob`
  (span count, color/format mapping), `text_mods_to_text_format`.
- **Render/widget tests** use `egui_kittest` (egui's official harness)
  for snapshot/interaction tests of the conversation log, prompt submit,
  screen-stack modal, and canvas texture painting.
- **Host/plugin/provider suites** are untouched and must stay green —
  they are the parity backstop for everything below the UI.
- **Manual parity checklist**: a written, per-screen checklist
  (home/log/prompt, each built-in screen, file view/edit, changelog
  markdown, LSP installer multi-select, canvas render + click) verified
  in the running window before the ratatui deps are removed.

## Implementation sequence (one spec, staged build)

1. **Shell skeleton.** `eframe::run_native` + tokio runtime handle +
   `SavvagentApp` with the existing `App`/`HostSlot`/`worker_rx`; empty
   `CentralPanel`; delete `tui.rs`. App launches to a window.
2. **Render model bridge.** Move slot/tool-summary computation to a
   background task feeding a cached `RenderModel` (§2).
3. **Render boundary.** egui sink in `convert.rs`, `Palette`→`Color32`,
   paint header + conversation log + tips + footer from the cached model.
4. **Input pipeline.** `egui_event_to_portable`, the routing tree,
   keybinding router, screen-stack `on_key`, Ctrl-C/Ctrl-D.
5. **Prompt.** `TextEdit::multiline` + history + submit semantics.
6. **Screen stack + modals.** Paint `Screen::render` lines + chrome as
   egui windows/panels (fullscreen / centered-modal / bottom-sheet
   variants).
7. **Heavy widgets.** Code editor (`egui_code_editor`), markdown
   (`egui_commonmark`), file picker, `MultiSelectList`.
8. **Canvas.** RGBA8 → `ColorImage`/`TextureHandle`, inline image,
   pointer→`MouseEventPortable`; delete `ratatui-image`/`coords.rs`/
   overlay plumbing.
9. **Teardown.** Remove ratatui/crossterm/tui-* deps, delete dead TUI
   code, run the parity checklist, fix fallout.

## Risks / open questions

- **Font & glyph fidelity.** The line-based log relies on box-drawing and
  status glyphs (`…`, `✓`, `✗`, borders). A bundled monospace (likely a
  Nerd Font subset) is needed so the monospace-row model looks right;
  otherwise badges/borders misalign. Bundling adds binary size.
- **Widget behavior gaps.** `egui_code_editor` and `egui_commonmark` are
  capable but not 1:1 with the ratatui crates; some behaviors (e.g.
  precise cursor/selection semantics, markdown edge cases) get
  reimplemented or accepted as minor differences.
- **Repaint cadence.** egui is idle-reactive; streaming turns must drive
  `request_repaint()`/`request_repaint_after` so tokens animate without
  spinning the CPU when idle. Needs a clear "is a turn live / channel
  non-empty" predicate.
- **Canvas event coverage.** `HtmlCanvas::dispatch` takes a
  `MouseEventPortable`; confirm the egui pointer → portable mapping
  covers hover, click, and scroll as Blitz expects.
- **Distribution.** cargo-dist artifacts gain a GUI binary; confirm
  Linux (wgpu/glow backend), macOS, and Windows packaging still produce
  one archive per platform, and that no terminal-only assumptions remain
  in the shim binaries.
- **Binary size / startup.** egui + wgpu + a bundled font is larger and
  has GPU-context startup cost vs a terminal binary; acceptable for a
  desktop GUI but worth measuring.

## Version & sequencing

Targets **v0.19.0**, beginning after sub-project D (external-plugins,
v0.18.0) has landed on master, so the two large initiatives do not edit
overlapping surfaces concurrently. Per the project's release discipline,
the version bump, CHANGELOG/release notes, and README/PRD updates ship in
the same change set that completes the migration; the tag is pushed only
when the work is complete (cargo-dist owns the release lifecycle on tag
push).
