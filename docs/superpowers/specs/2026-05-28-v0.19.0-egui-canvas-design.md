# egui Canvas — Design (v0.19.0, Plan 4 of 5)

Plan 4 of the five-plan egui front-end migration. Wires inline HTML canvases
into the egui shell with full Phase-2 parity: Blitz RGBA8 frames are uploaded
as egui textures and painted in the conversation log; mouse and keyboard input
are translated to portable events and routed through the existing
`ContentRenderer::dispatch` machinery; focus integration mirrors the TUI's
`InputMode::Canvas` state machine and the freeze/thaw lifecycle.

Sibling plans:

- Plan 1 (shipped, PR #104) — egui shell, render-model bridge, conversation
  log, footer, prompt, turn execution.
- Plan 2 (shipped, PR #105) — screen stack + modals.
- Plan 3 (shipped, PR #106) — heavy widgets (code editor, file picker, etc.).
- Plan 4 (this doc) — canvas textures + interaction.
- Plan 5 (future) — teardown: flip default to GUI, retype `Palette` to
  `Color32`, remove `ratatui`/`crossterm`/`ratatui-image`/`tui-*` deps,
  delete `coords.rs`, parity sweep.

## Goals

1. Replace the `[canvas — rendered in Plan 4]` placeholder in
   `crates/savvagent/src/egui_app/view.rs` with an actual rendered canvas.
2. Match the TUI's interaction surface: click-to-focus, Tab/BackTab traversal
   between focusable elements, Ctrl-J/K cycling between canvases, Ctrl-O
   open-in-browser, Esc to leave focus, plugin `OnFocusedCanvas` keybindings,
   raw key/mouse dispatch into the renderer.
3. Maintain the freeze/thaw discipline: any canvas that does not hold focus is
   frozen so it does not allocate per-frame DOM state.
4. Keep `App` and `savvagent-canvas` free of egui types — GUI texture state
   lives only inside `egui_app/`.

## Non-goals

- Removing `ratatui-image` or `coords.rs`. These remain Plan 5 work because
  the TUI still consumes them (see `crates/savvagent/src/ui.rs:1028`,
  `App::CanvasRegistry::image_protocol_mut`, and the TUI mouse-dispatch path
  at `crates/savvagent/src/main.rs:3120`).
- Hi-DPI scaling beyond `ctx.pixels_per_point()`. The texture is rendered at
  `panel_pts × pixels_per_point` and displayed at the source pixel size so it
  appears 1:1 at the current DPI. Per-monitor PPP changes invalidate the
  cache by the existing width-change rule.
- New canvas behaviours not in the TUI today (e.g. drag-to-select text inside
  the canvas, in-canvas search). Parity is the bar.

## Architecture

Approach B from the brainstorm: keep the renderer registry on `App`, build a
new GUI-side texture cache in `egui_app/widgets/canvas.rs`, factor the
shell-agnostic key/mouse handling into a new `crate::canvas_input` module so
both shells share it.

```
crates/savvagent/src/
├── canvas_input.rs                NEW — shell-agnostic dispatch
├── main.rs                        TUI calls canvas_input after crossterm
│                                  → portable translation
├── app.rs                         App::canvas_registry unchanged (still
│                                  owns renderers + ratatui state)
└── egui_app/
    ├── mod.rs                     SavvagentApp gains gui_canvas_cache;
    │                              clears it alongside canvas_registry.clear
    ├── view.rs                    Entry::Canvas arm calls
    │                              widgets::canvas::paint(...)
    └── widgets/
        ├── mod.rs                 + pub mod canvas;
        └── canvas.rs              NEW — GuiCanvasCache, paint(),
                                   event-translation glue
```

### `crate::canvas_input` (new module)

Two `async` functions, both shell-agnostic:

```rust
/// Built-in keys → plugin OnFocusedCanvas bindings → raw renderer dispatch.
/// Mirrors crates/savvagent/src/main.rs:3858 (the existing TUI handler) but
/// takes a portable key event instead of a crossterm one.
pub async fn handle_focused_canvas_key(
    app: &mut App,
    host_slot: &HostSlot,
    id: ContentBlockId,
    element_idx: Option<u32>,
    key: KeyEventPortable,
);

/// Forward a frame-pixel mouse event to the renderer and apply effects.
/// Mirrors the TUI mouse path at crates/savvagent/src/main.rs:3120.
pub async fn handle_canvas_mouse(
    app: &mut App,
    host_slot: &HostSlot,
    id: ContentBlockId,
    mouse: MouseEventPortable,
);
```

Both helpers borrow the renderer mutably, run the async dispatch, drop the
borrow, then call `apply_canvas_effects(app, host_slot, effects)` — the
existing TUI helper, which moves to a `pub(crate)` location accessible from
the new module.

The factor-out is a mechanical rename of the existing TUI bodies; the only
behavior change is that the function entry now accepts the portable event
type. The TUI's `crossterm::KeyEvent` → `KeyEventPortable` conversion
(`crate::plugin::convert::key_event_to_portable`) is performed by the
TUI caller, exactly as it does today.

### `egui_app/widgets/canvas.rs` (new module)

```rust
pub struct GuiCanvasCache {
    textures: HashMap<ContentBlockId, GuiTexEntry>,
}

struct GuiTexEntry {
    /// Pixel width the texture was rendered at. Cache miss when the desired
    /// width differs.
    width_px: u32,
    /// Pixel height of the texture (== Frame::height returned by Blitz at
    /// width_px). Stored for display sizing without re-querying the handle.
    height_px: u32,
    handle: egui::TextureHandle,
}

impl GuiCanvasCache {
    pub fn new() -> Self { ... }
    pub fn clear(&mut self) { ... }
    pub fn invalidate(&mut self, id: ContentBlockId) { ... }
}

/// Paint one canvas Entry into the current ui. Owns: cache miss/hit logic,
/// texture upload, image rendering, mouse + key event drain, focus
/// click-tracking, dispatch + dirty invalidation.
pub fn paint(
    ui: &mut egui::Ui,
    ctx: &egui::Context,
    app: &mut App,
    cache: &mut GuiCanvasCache,
    host_slot: &HostSlot,
    rt: &tokio::runtime::Handle,
    id: ContentBlockId,
    source: &str,
    source_preview: Option<&str>,
    palette: &Palette,
);
```

`paint` is called from `egui_app::view::paint_log` for every `Entry::Canvas`.
The streaming-preview branch (when `source_preview.is_some()`) takes the
same monospace-text path as `paint_role_block`, with a "Rendering HTML
canvas…" header, mirroring the TUI's `render_source_preview`. No Blitz call,
no texture, no event handling on a streaming canvas.

### `SavvagentApp` changes (`egui_app/mod.rs`)

Add one field:

```rust
pub struct SavvagentApp {
    // … existing fields …
    pub gui_canvas_cache: widgets::canvas::GuiCanvasCache,
}
```

Initialize it in `SavvagentApp::new`. Clear it everywhere
`app.canvas_registry.clear()` runs — today that's the start of
`App::replay_transcript`. A `pub(crate) fn clear_canvas_caches(&mut self)`
helper on `SavvagentApp` keeps the call site honest.

### `egui_app/view.rs` changes

Replace the placeholder in `paint_log` (currently `view.rs:240`) with a
borrow-careful call into `widgets::canvas::paint`. Because `paint_log` takes
`&SavvagentApp` today and the new code needs `&mut App` (for the renderer
borrow) and `&mut GuiCanvasCache`, `paint_log` must be retyped to
`&mut SavvagentApp`. Confirm none of its other paths require shared aliasing
into `app.entries` while paint runs — current shape is a `for entry in
&state.app.entries` loop that snapshots `model` from
`state.render_cache().lock().unwrap().clone()` first, so the entries iteration
can be done either by index or by collecting the `Entry::Canvas` ids up-front
to break the iteration borrow before calling the mutable canvas paint. The
plan implementation will choose the cheapest form; an outer-loop snapshot of
`(idx, id, source, source_preview)` for each canvas is the path of least
surprise.

## Data flow per frame

For each `Entry::Canvas { id, source, source_preview }` reached during the
log paint:

1. **Streaming?** If `source_preview.is_some()`, paint the preview text
   block and continue. No further Blitz/texture work.
2. **Empty?** If `source.is_empty()` and no preview, skip with a one-line
   `[empty canvas]` muted note (defensive — should not occur in practice).
3. **Compute desired width.** `width_pts = ui.available_width()`,
   `width_px = (width_pts * ctx.pixels_per_point()).floor().max(1.0) as u32`.
4. **Cache lookup.** `cache.textures.get(&id)`.
   - **Hit and `entry.width_px == width_px`:** reuse `entry.handle`,
     `entry.height_px`.
   - **Miss or width mismatch:**
     - Borrow the renderer: `let r = app.canvas_registry.get_mut(id)?;`.
       If absent, skip + `tracing::warn!`.
     - `frame = r.render(PixelSize { width: width_px, height: 0 });`
     - `let img = frame_to_color_image(&frame)?;` (silent skip on
       size mismatch, mirroring `frame_to_dynamic_image`).
     - `let handle = ctx.load_texture(format!("canvas-{}", id.0), img,
       egui::TextureOptions::LINEAR);`
     - Insert / replace `GuiTexEntry { width_px, height_px: frame.height,
       handle }`.
5. **Paint the texture.** `display_size = vec2(width_px as f32 / ppp,
   height_px as f32 / ppp);`. Add an `egui::Image::new(SizedTexture::new(
   handle.id(), display_size)).sense(Sense::click_and_drag())` and capture
   the `Response`.
6. **Focus click-tracking.**
   - `resp.clicked() && !app.is_canvas_focused(id)` → call
     `app.focus_canvas(id, None)`. `App::focus_canvas` already freezes any
     previously-focused canvas and thaws this one.
   - On click outside any canvas in the log panel, transition focus back to
     editor (via `app.unfocus_canvas()`). Detected by tracking
     `ctx.input(|i| i.pointer.any_pressed())` against
     `resp.rect.contains(pointer_pos)` for the canvas; an outer
     `paint_log`-level helper aggregates "did any canvas receive this click"
     and unfocuses if none did.
7. **Mouse event translation.** For each pointer event reported by
   `ctx.input(|i| ...)` whose position lies in `resp.rect`:
   - Translate to `MouseEventPortable { kind, button, x_pixel, y_pixel,
     modifiers }` with `x_pixel = ((point.x - resp.rect.min.x) * ppp) as u32`
     (same for `y_pixel`).
   - `rt.enter(); futures::executor::block_on(canvas_input::handle_canvas_mouse(
     app, host_slot, id, portable));` — matches the existing
     `block_on` pattern in `egui_app/mod.rs`.
   - After dispatch, if any handled mouse event might have mutated state,
     conservatively invalidate the cache for `id` (most dispatch paths
     return `dirty=true` for mouse interactions inside an interactive
     element; the wrapper inspects the returned `InputOutcome.dirty` and
     calls `cache.invalidate(id)` when set). For non-dirty mouse events,
     no invalidation.
8. **Keyboard event translation.** When `app.is_canvas_focused(id)`:
   - Drain the frame's key presses from `ctx.input(|i| &i.events)`.
   - For each `egui::Event::Key { key, pressed: true, modifiers, ... }`,
     translate to `KeyEventPortable` using a new
     `crate::egui_app::convert::egui_key_event_to_portable(...)` helper
     (or extend the existing `convert.rs`). Forward via
     `block_on(canvas_input::handle_focused_canvas_key(app, host_slot, id,
     element_idx, portable))`.
   - `element_idx` is read from `App::input_mode` (which is already
     `InputMode::Canvas { id, element_idx }` whenever a canvas is focused).
   - Built-in shortcuts (Esc, Tab, BackTab, Ctrl-J, Ctrl-K, Ctrl-O) are
     handled inside `canvas_input::handle_focused_canvas_key` exactly as
     they are in the current TUI handler. They never reach the GUI's other
     shortcut routing.
9. **Dirty invalidation.** When the dispatch outcome reports `dirty=true`,
   `cache.invalidate(id)`. Next frame re-renders.

## Frame → ColorImage

```rust
fn frame_to_color_image(frame: &Frame) -> Option<egui::ColorImage> {
    if frame.width == 0 || frame.height == 0 { return None; }
    let expected = (frame.width as usize)
        .checked_mul(frame.height as usize)?
        .checked_mul(4)?;
    if frame.bytes.len() != expected { return None; }

    let mut rgba = frame.bytes.clone();
    if matches!(frame.format, PixelFormat::Bgra8) {
        for px in rgba.chunks_exact_mut(4) { px.swap(0, 2); }
    }
    Some(egui::ColorImage::from_rgba_unmultiplied(
        [frame.width as usize, frame.height as usize],
        &rgba,
    ))
}
```

This mirrors `frame_to_dynamic_image` in `app.rs`; behaviour stays consistent
between the TUI's image bridge and the GUI's texture bridge.

## Focus integration

The existing `App::input_mode` carries `InputMode::Canvas { id, element_idx }`
and the existing methods `focus_canvas`, `unfocus_canvas`, `set_canvas_element`,
`is_canvas_focused` handle freeze/thaw transitions. The GUI uses these as-is.

Specifically:

- Click on a canvas inside the log → `app.focus_canvas(id, None)`.
  Freeze fires on any previously-focused canvas; thaw on this one.
- Click outside any canvas in the log → if currently focused on a canvas,
  call `app.unfocus_canvas()`.
- Built-in `Esc` → `app.unfocus_canvas()` (inside the shared
  `handle_focused_canvas_key`).
- Tab / BackTab → `app.set_canvas_element(cycle_index(...))` and
  `renderer.set_focus(...)`; logic lives in the shared module.
- Ctrl-J / Ctrl-K → `adjacent_canvas(&app.entries, id, dir)` →
  `app.focus_canvas(next, None)`. Same shared module.
- Ctrl-O → open-in-browser. Same shared module.

The GUI does **not** need its own focus state — it observes
`App::input_mode` and drives transitions through the same `App` methods.

## Error handling

| Failure | Behaviour |
|---|---|
| `app.canvas_registry.get_mut(id)` returns `None` | Skip the canvas with `tracing::warn!`. (Matches existing TUI behaviour at `main.rs:3136`, `:3960`.) |
| `frame_to_color_image` returns `None` (zero-size or mismatched byte length) | Skip the upload, leave the previous texture in place (if any), or draw a one-line muted `[canvas render failed]` note if no prior texture exists. `tracing::warn!`. |
| `renderer.dispatch(...)` returns `Err(_)` | `tracing::warn!`; no effects applied; no cache change. Matches existing TUI handlers. |
| Texture allocation panics (egui out-of-memory) | Not handled — egui will surface the panic to eframe; consistent with how the existing code handles unrecoverable paint failures. |

- `crates/savvagent/src/egui_app/widgets/canvas.rs` `#[cfg(test)] mod tests`:
  - `frame_to_color_image` round-trip for RGBA8.
  - `frame_to_color_image` byte-swap for BGRA8.
  - `frame_to_color_image` rejects zero-size and mismatched byte length.
  - `GuiCanvasCache::clear` removes every entry.
  - `GuiCanvasCache::invalidate(id)` removes only that entry.
  - Mouse coord translation: given `(rect, ppp, point)`, expected
    `(x_pixel, y_pixel)`; clamped + clipped variants.

  - Esc unfocuses; cache effect (via the shared `App` state) is testable.
  - Tab cycles `element_idx` modulo focusable count; BackTab cycles backward.
  - Ctrl-J/K move focus to the adjacent canvas in `app.entries`; no-op when
    only one canvas exists.
  - Ctrl-O records the expected `Note` entry on the supplied app stub.

## Risks / open items

1. **Borrow shape in `paint_log`.** `&mut App` is needed for renderer
   access; the placeholder code today uses `&App`. The implementation must
   either (a) restructure `paint_log` to take `&mut SavvagentApp` (preferred,
   matches `paint_prompt`) or (b) collect canvas ids out of the entry loop
   first and process them in a second pass. Plan implementation chooses
   based on what's least invasive.
2. **`futures::executor::block_on` on a `&mut App`.** The existing
   `block_on` in `egui_app/mod.rs` runs against the worker drain, not against
   a mutex-guarded shared `App`. Here it must run inside the paint
   pass with a live `&mut App` borrow held. The async dispatch only awaits
   the renderer (not any other `App`-bound future), so reentrancy is not
   possible. Confirm with a comment at the call site.
3. **Egui texture leak across `/resume`.** If `clear_canvas_caches` is
   forgotten anywhere `App::canvas_registry.clear` runs, the GUI keeps
   stale handles whose ids point at freed renderers. The shared
   `SavvagentApp::clear_canvas_caches` helper bundles both calls so future
   sites can't drift.
4. **Plugin `OnFocusedCanvas` access to async plugin indexes.** The TUI
   handler reads `app.plugin_indexes.read().await`. Reusing the same
   handler under `block_on` preserves the await — fine, but it's a
   nested-await pattern worth flagging in implementation.
5. **`egui::Key` → `KeyEventPortable` translator.** No such helper exists
   yet (Plan 1 added the inverse for the prompt). Adding it lives inside
   this plan; it must cover the same character/key-code surface as the
   TUI's crossterm converter.

## Done criteria

- `cargo run -p savvagent gui` opens a window where an `Entry::Canvas` in the
  log paints as a bitmap from Blitz (no longer the
  `[canvas — rendered in Plan 4]` placeholder).
- Resizing the window re-renders the canvas at the new width within one frame
  of input idle.
- Clicking on the canvas focuses it (the canvas is thawed; any previously
  focused canvas is frozen). Esc unfocuses. Tab traverses focusable
  elements. Ctrl-J/K hop to adjacent canvases. Ctrl-O opens the canvas's
  source in the system browser.
- Keyboard typing inside a focused canvas reaches the renderer (e.g. typing
  into a focused `<input>` updates the rendered frame on the next paint).
- Mouse clicks inside the canvas reach the renderer with frame-pixel
  coordinates.
- `cargo test --workspace`, `rustup run stable cargo fmt --check`,
  `rustup run stable cargo clippy --workspace --all-targets` all green.
- The TUI canvas path is unchanged (its tests stay green and behaviour
  matches the previous release).
